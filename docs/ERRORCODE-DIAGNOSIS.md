## ۳. پنج مکانیسمِ تولیدِ محتوای کپی/نامرتبط

این‌ها همان چیزی است که درخواست شما («کپی از خطاهای دیگر ممنوع»، «برای ایراد تخلیه
ایراد شیربرقی ننویسد») دقیقاً به آن اشاره دارد:

### 🔴 ۳.۱ `deviceCauses()` — یک لیست ثابت برای **همه** کدهای یک دستگاه

**`engine/generators/ErrorCodeEngine.php:2018-2032`**

```php
private function deviceCauses(string $deviceKey, string $category): array
{
    $common = [
        'washing_machine' => ['گرفتگی فیلتر یا مسیر تخلیه',
                              'خرابی شیر برقی ورودی آب',
                              'فرسودگی سنسور فشار آب',
                              'خرابی قفل درب',
                              'اشکال برد کنترل'],
        ...
    ];
    return $common[$deviceKey] ?? [...];
}
```

دو مشکلِ هم‌زمان:

1. **`$category` پذیرفته شده اما هرگز استفاده نمی‌شود** — پارامتر کاملاً بلااستفاده است.
2. **کد خطا هیچ نقشی ندارد** — نتیجه فقط به دستگاه بستگی دارد.

**نتیجه‌ی ملموس:** هر کدِ لباسشویی که داده‌ی curated نداشته باشد، همین ۵ علت را می‌گیرد.
برای کد `OE` (عدم تخلیه) سیستم **«خرابی شیر برقی ورودی آب» و «خرابی قفل درب»** را هم می‌نویسد —
دقیقاً همان مثالِ نقضی که در درخواست آورده‌اید.

### 🔴 ۳.۲ `buildRecord()` — پُر کردنِ اجباری تا ۵ علت / ۵ راه‌حل

**`ErrorCodeEngine.php:1860-1868` (علت‌ها) و `:1850-1857` (راه‌حل‌ها)**

```php
$causePool = $this->deviceCauses($deviceKey, $c['category'] ?? 'سایر');
$ci = 0;
while (count($causes) < 5 && $ci < count($causePool)) {
    if (!in_array($causePool[$ci], $causes, true)) {
        $causes[] = $causePool[$ci];       // ← علتِ عمومی به علت‌های اختصاصی چسبانده می‌شود
    }
    $ci++;
}
```

بدتر از ۳.۱: حتی اگر یک کد، ۳ علتِ **کاملاً دقیق و اختصاصی** از وب یا پایگاه دانش داشته باشد،
سیستم دو علتِ عمومیِ دیگر را به آن **می‌چسباند** تا به حد نصابِ ۵ برسد.
سطر ۱۸۶۴ هم یک علتِ ثابتِ دیگر اضافه می‌کند:
`قطع برق طولانی و روشن‌سازی مجدد (ریست کامل برد)` — که در بسیاری از کدها ربطی ندارد.

همین الگو برای راه‌حل‌ها با `deviceUserFixes()` و `deviceTechFixes()` تکرار می‌شود.

### 🔴 ۳.۳ `composeDescription()` — یک چرخ‌دنده‌ی ۹۰ حالته

**`ErrorCodeEngine.php:1959-1991`**

```php
$openers = [ ۳ قالب ];
$mids    = [ ۲ قالب ];
$severityText = [ ۵ قالب ];
$closers = [ ۳ قالب ];

return $openers[$seed % 3] . ' ' . $mids[($seed >> 2) % 2] . ' ' . $severityText[$severity] . ' ' . $closers[($seed >> 3) % 3];
```

توضیحات از ترکیبِ **۳ × ۲ × ۵ × ۳ = ۹۰ حالت** ساخته می‌شوند و `$seed` از
`crc32(brand|device|code)` می‌آید. برای یک دستگاه با ۱۲ کد، یعنی ۱۲ متن که
ساختارِ جمله‌بندی‌شان یکی است و فقط نامِ قطعه و کد عوض می‌شود.

این دقیقاً همان چیزی است که گوگل به‌عنوان **「thin / templated content」** شناسایی می‌کند —
حتی اگر کلمات متفاوت باشند.

علاوه بر این، `$mids` از `$causes[0]` استفاده می‌کند؛ پس اگر ۳.۲ باعث شده باشد
`causes[0]` عمومی شود، **توضیف هم عمومی می‌شود**.

### 🟠 ۳.۴ `fallbackModels()` — یک رشته‌ی جایگزین به‌جای مدل واقعی

**`ErrorCodeEngine.php:2270-2273`**

```php
private function fallbackModels(string $brandFa, string $deviceKey): array
{
    return ['مدل‌های هم‌خانواده — با جستجوی آنلاین مدل‌ دقیق تکمیل شود'];
}
```

خروجیِ عملیِ فیلد ۴ برای ۹۹٪ کدها همین جمله است — نه ۳ مدل واقعی.

### 🟠 ۳.۵ `fallbackSpecs()` و `fallbackLocation()` — ۶ مقدار برای همه چیز

**`ErrorCodeEngine.php:2318-2350`**

```php
'سنسور' => 'مقاومت NTC: ۵-۱۲ kΩ در ۲۵°C (بسته به مدل)',
'پمپ'   => 'مقاومت کویل: ۱۵-۲۰ اهم · ولتاژ ۲۲۰V AC',
...
'سنسور' => 'روی/کنار قطعه هدف (طبق نقله مونتاژ)',
'موتور' => 'پشت دیگ',
```

هر کدی با دسته‌ی «سنسور» — در هر برند، هر دستگاه — **متنِ مشخصات و محلِ یکسان** می‌گیرد.

## ۵. جمع‌بندی: ریشه در یک جمله

> موتور فعلی **«داده‌محور» نیست، «قالب‌محور» است**.
> برای هر کد، یک زنجیره‌ی خرابی استنتاج نمی‌کند؛ در عوض یک قالب برمی‌دارد و
> جاهای خالی را با **(الف)** یک لیستِ ثابتِ مخصوصِ دستگاه، **(ب)** یک چرخ‌دنده‌ی
> ۹۰ حالته، و **(ج)** یک مقدار fallback مخصوصِ دسته پر می‌کند.
>
> برای همین:
> - علت‌ها به کد ربط ندارند (۳.۱ و ۳.۲)
> - متن‌ها شبیه هم‌اند (۳.۳)
> - مدل‌ها و مشخصات فنی واقعی نیستند (۳.۴ و ۳.۵)

**راه‌حلِ کوتاه‌مدت** (همین هفته): پرامپتِ `ERRORCODE-PROMPT.md` را اجرا کنید و خروجی را
بعد از رفعِ موانعِ بخش ۶ وارد کنید.

**راه‌حلِ ریشه‌ای** (بعدی): چهار تابعِ `deviceCauses` / `deviceUserFixes` / `deviceTechFixes` /
`composeDescription` / `fallbackModels` / `fallbackSpecs` / `fallbackLocation` را
از «تولیدکننده» به **「آخرین پناه」** تنزل دهید:
یعنی فقط وقتی صدا شوند که منبعِ واقعی (وبِ تأییدشده یا پایگاه دانش curated)
برای **همان کد** چیزی ندارد — و در آن صورت هم رکورد با برچسبِ
`source='fallback'` علامت بخورد تا در پنل قابل شناسایی و بازبینی باشد.
