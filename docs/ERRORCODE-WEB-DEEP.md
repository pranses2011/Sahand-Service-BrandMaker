# 🌐 جستجوی عمیق اینترنتیِ کدهای خطا (v2.34)

> مستندِ فنیِ مسیرِ وب در موتور خطایاب — از کوئری تا رکوردِ ۱۴ فیلدی.
> مخاطب: هر کسی که می‌خواهد **منبع یا زبانِ جدید** اضافه کند یا رفتارِ جستجو را بفهمد.

## ۱. نقشه‌ی مسیر

```
admin/error-codes.php  (select: عمق جستجو = fast | balanced | deep)
        │
        ▼
ErrorCodeEngine::generateForDevice(..., $depth)
        │
        ├── depthProfile($depth)          ← پروفایلِ عددیِ جستجو
        ├── searchWebCodes(..., ['depth' => $depth])
        │        │
        │        ├── buildDiscoveryQueries()   ← فارسی + انگلیسی از فایل دانش
        │        ├── WebSearchService::search($q, 10, ['lang'=>…,'engines'=>…,'deadline'=>…])
        │        │        └── searchWide()     ← ۱ یا ۲ موتور، ادغام + حذف تکراری
        │        ├── فیلترِ دامنه‌های بی‌فایده (stop_domains) + گاردِ زمینه (برند/دستگاه)
        │        ├── sourceMeta($url)          ← رسمی / دفترچه / قطعات / انجمن / فارسی
        │        ├── extractCodePatterns()     ← کشفِ کدها از اسنیپت‌ها
        │        ├── fetchPageText(صفحات فهرست) ← متن کامل تا ۱۶هزار نویسه
        │        │        ├── parseCodeTable()  ← جدولِ کدها (دقیق‌ترین منبعِ معنا)
        │        │        └── تور ایمنیِ الگویی روی کل متن
        │        └── deepResearchCode(هر کد)
        │                 ├── buildCodeQueries()   ← ۲ تا ۸ کوئریِ اختصاصیِ همان کد
        │                 ├── fetchPages()          ← ۱ تا ۴ صفحه با بودجه‌ی مشترک
        │                 ├── bestCodeWindow()      ← بهترین پنجره‌ی «دورِ خود کد»
        │                 └── englishMeaningFor()   ← «OE = Drain Error»
        ├── mergeKbIntoWebRecord()     (فقط پُر کردنِ فاصله‌ها)
        └── buildRecord()
                 ├── ErrorCodeSubsystem::resolve(عنوان فارسی)
                 ├── ErrorCodeSubsystem::resolve(معنای انگلیسی)  ← اگر قطعیت کافی نبود
                 └── ۱۴ فیلد (مشخصات/مدل/محل از پنجره‌ی خود کد مقدم‌اند)
        │
        └── درجِ تدریجی در error_codes (هر کد همان لحظه)
```

## ۳. فایل دانشِ منابع — `engine/knowledge/errorcode-web-sources.json`

همه‌ی الگوها و فهرست‌ها اینجا هستند؛ **برای تغییر نیازی به دستکاریِ کد نیست**.

| کلید | کاربرد |
|------|--------|
| `discovery_queries.en` / `.fa` | الگوهای کشف (یکی‌درمیان اجرا می‌شوند) |
| `code_queries.en` / `.fa` | الگوهای اختصاصیِ یک کد |
| `verticals[]` | سایت‌های عمودی: `{domain, kind, trust, booster_en}` — برای کوئریِ هدفمند و امتیاز اعتماد |
| `official_domains{brand}` | دامنه‌های رسمیِ هر برند (بالاترین اعتماد) |
| `stop_domains[]` | دامنه‌های بی‌فایده (یوتیوب، دیوار، آمازون، …) |
| `trust{}` | امتیازِ هر نوع منبع: رسمی ۱۰۰، دفترچه ۸۵، قطعات ۷۲، انجمن ۵۸، فارسی ۶۲، سایر ۳۴ |

**جای‌گذارها (placeholder):** `{brand}`، `{brand_fa}`، `{device}`، `{device_fa}`، `{code}`

### ➕ افزودن یک منبعِ جدید (بدون تغییر کد)

```json
{
  "key": "mysite",
  "domain": "example-repair.com",
  "lang": "en",
  "kind": "forum",
  "trust": 60,
  "booster_en": "example repair error code",
  "booster_fa": ""
}
```

کافی است یک شیء به آرایه‌ی `verticals` اضافه کنید — هم به عنوان کوئریِ عمودی
(در حالت عمیق) استفاده می‌شود و هم نتایجش امتیازِ اعتمادِ مناسب می‌گیرند.

### ➕ افزودن دامنه‌ی رسمیِ یک برند

```json
"official_domains": { "mybrand": ["mybrand.com", "mybrand-support.com"] }
```

### 🌍 درباره‌ی زبان‌ها

در حال حاضر **فارسی + انگلیسی** پشتیبانی می‌شود (انتخابِ شما).
افزودن زبانِ دیگر بعداً فقط دو گام دارد:
1. افزودن کلیدِ زبان به `discovery_queries` / `code_queries` (مثلاً `"tr"`)
2. افزودن نگاشتِ `lang → منطقه` در `WebSearchService::bingMarket()` و
   `effectiveRegion()` (برای hl/gl/mkt/kl)

## ۴. زبان و منطقه در موتورها (WebSearchService v1.6)

| موتور | پارامترها | فارسی | انگلیسی |
|-------|-----------|-------|---------|
| Google | `hl`, `gl` | `hl=fa&gl=IR` | `hl=en&gl=US` |
| Bing | `setlang`, `cc`, `mkt` | `fa`, `IR`, `fa-IR` | `en`, `US`, `en-US` |
| DuckDuckGo | `kl` | `fa-ir` | `us-us` |
| SearXNG | `language` | `fa` | `en` |
| Startpage | `language` | `farsi` | `english` |
| Wikipedia | دامنه | `fa.wikipedia.org` | `en.wikipedia.org` |

همه از `$opts['lang']` در `search()` می‌آیند:

```php
$searcher->search($query, 10, [
    'lang'     => 'fa',                 // یا 'en'
    'engines'  => 2,                    // حالت عمیق: ادغام دو موتور
    'deadline' => microtime(true) + 60, // بودجه زمانی
]);
```

## ۵. ادغام شواهد — چه کدی پذیرفته می‌شود؟

`ErrorCodeEngine::webEvidenceOk()`:

| شرط | پذیرش |
|-----|:-----:|
| معنا از **جدولِ کدهای** یک صفحه استخراج شده | ✅ |
| حداقل یک منبع **رسمی** یا **دفترچه** | ✅ |
| **حداقل ۲ دامنه‌ی مستقل** | ✅ |
| پایگاه دانشِ تخصصی آن کد را می‌شناسد | ✅ |
| زیرساختِ جستجو پاسخ نداد (بلاک/نرخ) | ✅ (اما `needs_review`) |
| یک منبعِ ضعیف و بس (امتیاز < ۸) | ❌ رد |

امتیازِ هر شاهد = `round(trust / 12)` + `۳` اگر از صفحه‌ی اختصاصیِ کد باشد،
`۲` اگر از صفحه‌ی فهرست باشد.

## ۶. جلوگیری از «نشتِ کدِ همسایه»

صفحه‌ی فهرستِ کدها شرحِ **همه** کدها را دارد. سه لایه محافظت:

1. `codeCentricContext()` — فقط پنجره‌ی ±متنِ دورِ خودِ کد خوانده می‌شود
2. `bestCodeWindow()` — از بین صفحات، پنجره‌ای برنده است که بیشترین تکرارِ
   خودِ کد و واژگانِ خطا/تعمیر را دارد
3. مشخصات/مدل/محلِ قطعه **فقط** از آن پنجره استخراج می‌شوند
   (`_specs_web`, `_models_web`, `_location_web`)

## ۷. عیب‌یابی

| نشانه | علتِ محتمل | اقدام |
|-------|-----------|-------|
| «هیچ کدی تأیید نشد» | موتورهای رایگان IP هاست را بلاک کرده‌اند | کلید SerpApi/Google CSE/Bing را ثبت کنید، یا از پلِ `r.jina.ai` (خودکار) استفاده می‌شود — چند دقیقه بعد دوباره تلاش کنید |
| «سقف نرخ جستجوی وب پر شد» | ۳۶۰ جستجو در ساعت | نتایج ۳۰ دقیقه کش می‌شوند؛ کمی بعد دوباره اجرا کنید (ادامه می‌دهد) |
| کدهای کم اما درست | موتورها محدودند | عمق را «عمیق» کنید؛ یا `verticals` را با سایت‌های همان برند گسترش دهید |
| فیلدهای مشخصات خالی | هیچ عددی در پنجره‌ی کد نبود | طبیعی است — زیرسیستمِ علّی مقدارِ واقعی را می‌دهد؛ اگر باز هم خالی ماند، کد `needs_review` می‌شود |
